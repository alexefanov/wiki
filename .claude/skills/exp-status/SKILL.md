# /exp-status

> Единая точка входа для мониторинга статуса экспериментов.
> Сканирует все эксперименты со статусом `running`, выполняет проверку статуса в реальном времени для каждого (сессия screen / SSH),
> и выводит таблицу статуса (alive / anomaly / completed) для ориентирования в действиях пользователя.
>
> При использовании с `/research --auto` выступает как периодический проверщик, планируемый через CronCreate:
> когда все эксперименты в пайплайне завершены, автоматически запускает `/research --start-from stage4`.

## Входы

- Без аргументов (по умолчанию): проверка всех экспериментов со статусом `running`, вывод таблицы статуса
- `--pipeline <slug>` (опционально): проверка только экспериментов, принадлежащих указанному пайплайну; дополнительно вывод общий прогресс пайплайна
- `--collect-ready` (опционально): авто-вызов `/exp-run --collect` для всех экспериментов, чья сессия уже завершилась
- `--auto-advance` (опционально, требует `--pipeline <slug>`): если все эксперименты пайплайна `completed`,
  автоматически запускает `/research --start-from stage4` без ожидания пользователя

## Выходы

- **Отчёт о статусе** (вывод в терминал, все режимы): список экспериментов в состояниях running/anomaly/completed
- `wiki/experiments/{slug}.md` — обновлённый (outcome/key_result/status) когда `--collect-ready` запускает Этап 4
- `wiki/outputs/pipeline-progress.md` — `--auto-advance` обновляет current_stage → stage4 (выполняется внутри /research --start-from stage4)
- `wiki/log.md` — добавлена запись в журнал проверки статуса

## Взаимодействие с Wiki

### Чтение
- `wiki/experiments/*.md` — статус, удалённый frontmatter (server/session/started), date_planned
- `wiki/outputs/pipeline-progress.md` — в режиме `--pipeline` определяет целевые эксперименты и monitoring_cron_id

### Запись
- `wiki/experiments/{slug}.md` — обновление через /exp-run --collect в режиме `--collect-ready`
- `wiki/outputs/pipeline-progress.md` — обновляется /research при `--auto-advance` на стадии 4
- `wiki/log.md` — добавлена запись в журнал проверки статуса

### Создаваемые графовые рёбра
- Нет (записи результатов, запускаемые косвенно через /exp-run --collect, не создают новых рёбер)

## Рабочий процесс

**Предусловие**: убедитесь, что рабочая директория — корень проекта wiki (директория, содержащая `wiki/`, `raw/`, `tools/`).

### Шаг 1: Сбор целевого списка экспериментов

1. **Определение объёма проверки**:
   - Если указан `--pipeline <slug>`:
     - Прочитайте `wiki/outputs/pipeline-progress.md`, извлеките список slug'ов из поля `stage3a_deployed`
     - Если файл не существует или slug не совпадает: сообщите об ошибке, предложите сначала запустить `/research` или указать вручную
   - Иначе:
     - Используйте Glob для сканирования `wiki/experiments/*.md`, фильтр `status == running`

2. **Если нет запущенных экспериментов**:
   - Выведите дружелюбное сообщение:
     ```
     Запущенные эксперименты не найдены.
     - Для запуска эксперимента: /exp-run <slug>
     - Для просмотра всех экспериментов: проверьте wiki/experiments/
     ```
   - Возврат

### Шаг 2: Проверка статуса каждого эксперимента

Для каждого целевого эксперимента выполните параллельно (или последовательно):

1. **Чтение страницы эксперимента**: из `wiki/experiments/{slug}.md` получите:
   - Блок `remote` (если присутствует, это удалённый эксперимент)
   - Путь `run_log`
   - `started` (из `remote.started` или `date_planned`, используется для вычисления прошедшего времени)
   - Среда развёртывания (есть блок remote → remote, иначе → local)

2. **Проверка статуса процесса**:
   - **Локальный**: `screen -ls | grep "exp-{slug}"`
     - Есть вывод → `alive: true`
     - Нет вывода → `alive: false` (сессия исчезла)
   - **Удалённый**: `python3 tools/remote.py check --name "exp-{slug}"`
     - Парсинг JSON: `alive`, `last_lines`, `anomalies`

3. **Если alive == true**:
   - Получите последние логи (максимум 20 строк):
     - Локальный: `tail -20 {run_log}`
     - Удалённый: используйте `last_lines` из ответа команды `check`
   - Извлеките последнюю метрику (loss, accuracy, шаг и т.д. — grep последней строки метрики)
   - Обнаружение аномалий (NaN/OOM/Traceback/Inf): используйте поле `anomalies` из `remote.py check` (удалённый) или ручной grep (локальный)
   - Вычисление прошедшего времени (текущее время − started)
   - Классификация: `running` или `anomaly`

4. **Если alive == false**:
   - Классификация: `completed_pending_collect` (сессия исчезла, но статус wiki всё ещё running)
   - Если статус wiki уже `completed`: классификация `collected`

5. **Агрегация результатов**: построение словаря статуса `{slug: {state, elapsed, latest_metric, anomalies}}`

### Шаг 3: Вывод отчёта о статусе

```markdown
# Статус экспериментов — {YYYY-MM-DD HH:MM}

### 🔄 Запущены ({N})
| Эксперимент | Прошло | Последний | Среда |
|-------------|--------|-----------|-------|
| [[exp-foo-baseline]] | 2.3ч | loss: 0.42 | local |
| [[exp-foo-validation]] | 1.1ч | шаг: 1200 | remote (gpu1) |

### ⚠️ Обнаружены аномалии ({N})
| Эксперимент | Прошло | Проблема | Действие |
|-------------|--------|----------|----------|
| [[exp-foo-ablation]] | 0.8ч | NaN loss на шаге 500 | Запустите `/exp-run exp-foo-ablation --collect` для проверки |

### ✅ Завершены — Ожидают сбора ({N})
| Эксперимент | Завершён (оценка) |
|-------------|-------------------|
| [[exp-foo-sanity]] | сессия исчезла |

### 📦 Уже собраны ({N})
| Эксперимент | Результат |
|-------------|-----------|
| [[exp-foo-old]] | succeeded |

### Действия
```bash
# Собрать все завершённые эксперименты сразу:
/exp-status --collect-ready

# Собрать конкретный эксперимент:
/exp-run exp-foo-sanity --collect

# Прогресс пайплайна (если в /research):
/exp-status --pipeline {pipeline-slug}
```
```

Добавление в журнал:
```bash
python3 tools/research_wiki.py log wiki/ \
  "exp-status | running: {N}, anomaly: {M}, pending-collect: {K}"
```

### Шаг 4: --collect-ready авто-сбор (если указан)

Для каждого эксперимента `completed_pending_collect` вызовите `/exp-run --collect`:

```
Skill: exp-run
Args: "{slug} --collect"
```

Собирайте каждый завершённый эксперимент последовательно (не параллельно, для избежания конкурентных записей в wiki).

После завершения всех сборов повторно выведите обновлённый отчёт о статусе.

### Шаг 5: --auto-advance продвижение пайплайна (если указаны оба --pipeline и --auto-advance)

1. **Проверка условия завершения пайплайна**:
   - Прочитайте список `stage3a_deployed` из `wiki/outputs/pipeline-progress.md`
   - Проверьте статус каждого slug'а в `wiki/experiments/{slug}.md`
   - **Условие выполнено**: все эксперименты имеют статус == `completed`

2. **Если условие не выполнено** (некоторые эксперименты всё ещё запущены или ожидают сбора):
   - Выведите текущий прогресс: `Пайплайн {slug}: {M}/{N} экспериментов завершено`
   - Возврат (не продвигайтесь)
   - Cron снова запустится через 30 минут

3. **Если условие выполнено (все эксперименты завершены)**:

   a. **Вывод уведомления и запуск стадии 4**:
   - Вывод:
     ```
     ✅ Все эксперименты завершены для пайплайна {slug}!
     Продвижение к стадии 4 (Вердикт и итерация)...
     ```
   - Добавление в журнал:
     ```bash
     python3 tools/research_wiki.py log wiki/ \
       "exp-status | пайплайн {slug}: все эксперименты завершены, продвижение к stage4"
     ```
   - Запуск следующей стадии:
     ```
     Skill: research
     Args: "--start-from stage4"
     ```

## Ограничения

- **Только чтение в режиме без --collect-ready**: без `--collect-ready` не изменяйте какие-либо файлы wiki
- **`--auto-advance` требует `--pipeline`**: использование `--auto-advance` само по себе недопустимо, сообщите об ошибке
- **Проверки статуса должны быть неблокирующими**: проверка каждого эксперимента должна завершаться быстро (один SSH-вызов или screen -ls)
- **Аномалии не исправляются автоматически**: `/exp-status` только сообщает об аномалиях; исправления требуют ручного вызова пользователем `/exp-run --collect`
- **pipeline-progress.md должен существовать**: в режиме `--pipeline`, если файл отсутствует, сообщите об ошибке

## Обработка ошибок

- **Нет запущенных экспериментов**: выведите дружелюбное сообщение, а не ошибку; предложите следующие шаги
- **`--pipeline`, но pipeline-progress.md не существует**: сообщите об ошибке "Файл прогресса пайплайна не найден. Сначала запустите `/research <направление>` или проверьте wiki/outputs/"
- **`--auto-advance` без `--pipeline`**: сообщите об ошибке "--auto-advance требует --pipeline <slug>"
- **SSH-подключение не удалось** (удалённый эксперимент): пометьте этот эксперимент как `check_failed`, отметьте в отчёте, продолжайте проверку других экспериментов
- **screen -ls ничего не возвращает**: это не означает, что эксперимент провалился — возможно, кратковременная задержка; пометьте как `completed_pending_collect`
- **`/exp-run --collect` завершился ошибкой** (режим `--collect-ready`): запишите ошибку, продолжайте сбор других экспериментов, сообщите обо всех ошибках в конце

## Зависимости

### Навыки (через инструмент Skill)
- `/exp-run` — вызов фазы сбора в режиме `--collect-ready`
- `/research` — запуск стадии 4 через `--auto-advance`

### Инструменты (через Bash)
- `python3 tools/remote.py check --name "exp-{slug}"` — проверка статуса удалённого эксперимента
- `python3 tools/remote.py tail-log --name "exp-{slug}" --lines 20` — получение удалённых логов
- `python3 tools/research_wiki.py set-meta <path> <field> <value>` — обновление pipeline-progress
- `python3 tools/research_wiki.py log wiki/ "<message>"` — добавление в журнал
- `screen -ls` — статус локальных процессов
- `tail -20 {log}` — получение локальных логов

### Claude Code Native
- `Read` — чтение страниц экспериментов и pipeline-progress
- `Write` — обновление статуса pipeline-progress
- `Glob` — сканирование wiki/experiments/*.md
- `Bash` — screen/tail и другие системные команды
- `Skill` — вызов /exp-run --collect и /research

### Вызывается из
- Расписание CronCreate (создано через `/research --auto` Стадия 3b: запуск каждые 30 минут)
- Пользователь напрямую
- `/research` Стадия 3b (в интерактивном режиме, предложено пользователю)
