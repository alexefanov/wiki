# /paper-draft

> Черновик полной LaTeX-статьи из PAPER_PLAN.md, сгенерированного /paper-plan.
> Написание по разделам: каждый раздел черпает материал из идей/методов/экспериментов/статей/концепций wiki,
> генерирует LaTeX + фигуры + таблицы. BibTeX извлекается из DBLP/CrossRef (согласно citation-verification).
> Применяется удаление AI-маркеров после завершения (согласно academic-writing).
> Опциональная проверка каждого раздела Review LLM. Вывод компилируемой директории paper/.

## Входы

- `plan`: путь к PAPER_PLAN.md (например, `wiki/outputs/paper-plan-sparse-lora-2026-04-08.md`)
- `--review` (опционально): включение посекундной проверки Review LLM
- `--sections` (опционально): написание только указанных разделов (например, `--sections 3,4` — только Method + Experiments); используется для инкрементального написания

## Выходы

- Директория `paper/` (в корне проекта wiki):
  - `paper/main.tex` — мастер-файл (включает каждый раздел)
  - `paper/sections/introduction.tex`
  - `paper/sections/related_work.tex`
  - `paper/sections/method.tex`
  - `paper/sections/experiments.tex`
  - `paper/sections/conclusion.tex`
  - `paper/sections/appendix.tex` (если применимо)
  - `paper/figures/` — сгенерированные фигуры (PDF/PNG)
  - `paper/tables/` — отдельные файлы таблиц (опционально)
  - `paper/math_commands.tex` — общие определения математических символов
  - `paper/references.bib` — верифицированные записи BibTeX
- `wiki/log.md` — добавлена запись в журнал

## Рабочий процесс

**Предусловие**: убедитесь, что рабочая директория — корень проекта wiki (директория, содержащая `wiki/`, `raw/`, `tools/`).

### Шаг 1: Инициализация директории статьи

1. Прочитайте PAPER_PLAN.md; извлеките площадку, заголовок, список разделов
2. Если директория `paper/` уже существует:
   - Резервное копирование как `paper.bak-{timestamp}/`
   - Предложите пользователю подтвердить перезапись
3. Создайте структуру директорий:
   ```
   paper/
   ├── main.tex
   ├── math_commands.tex
   ├── references.bib
   ├── sections/
   └── figures/
   ```
4. Скопируйте шаблон площадки из `templates/` если он существует:
   - `templates/{venue}.sty` или `templates/{venue}/`
   - Если шаблона нет: используйте универсальный класс article; укажите в main.tex, что необходимо заменить на официальный шаблон
5. Генерация `math_commands.tex`:
   - Сбор обозначений из wiki/methods/ (`## Mechanism`, `## Procedure`) и wiki/concepts/ (`## Definition`, `## Intuition`)
   - Унификация определений символов (векторы, матрицы, множества, общие операторы)
6. Генерация каркаса `main.tex`:
   ```latex
   \documentclass{article} % замените на шаблон площадки
   \input{math_commands}
   % пакеты
   \usepackage{booktabs,graphicx,amsmath,hyperref}

   \title{<название>}
   \author{} % оставьте пустым для анонимной подачи

   \begin{document}
   \maketitle
   \begin{abstract}
   % генерируется на шаге 3
   \end{abstract}
   \input{sections/introduction}
   \input{sections/related_work}
   \input{sections/method}
   \input{sections/experiments}
   \input{sections/conclusion}
   \bibliography{references}
   \bibliographystyle{plain} % замените на стиль, требуемый площадкой
   % \input{sections/appendix} % раскомментируйте при необходимости
   \end{document}
   ```

### Шаг 2: Генерация фигур и таблиц

Для каждой записи в плане фигур из PAPER_PLAN:

1. **Тип диаграммы** (архитектурные диаграммы и т.д.):
   - Используйте TikZ или pgfplots для генерации нативных фигур LaTeX
   - Если слишком сложно: сгенерируйте скрипт matplotlib на Python → вывод PDF
   - Сохраните в `paper/figures/{figure-name}.pdf`

2. **Тип графика** (графики результатов экспериментов):
   - Извлеките данные из `wiki/experiments/{slug}.md`
   - Сгенерируйте скрипт matplotlib (следуя стандартам дизайна фигур в academic-writing):
     - Палитра, безопасная для дальтоников
     - Размер шрифта >= 8pt
     - Строки погрешностей / доверительные интервалы
     - Понятная легенда
   - Выполните скрипт для генерации PDF:
     ```bash
     python3 paper/figures/plot_{name}.py
     ```
   - Сохраните в `paper/figures/{figure-name}.pdf`

3. **Тип таблицы**:
   - Используйте стиль booktabs (toprule, midrule, bottomrule)
   - Лучший результат жирным, второй — подчёркнутый
   - Встраивание напрямую в .tex файл раздела (небольшие таблицы) или отдельный `paper/tables/{name}.tex` (большие таблицы)

### Шаг 3: Написание разделов

Для каждого раздела (в порядке плана из PAPER_PLAN); если указан `--sections`, пишите только эти разделы:

**3a. Сбор материала**

Из определения раздела в PAPER_PLAN извлеките:
- поддерживаемые этой идеей идеи
- список соответствующих wiki-страниц
- запланированные фигуры/таблицы
- список цитат

Прочитайте релевантные части всех связанных wiki-страниц:
- Введение → wiki/ideas/{idea}.md (Hypothesis, Motivation, Novelty argument) + wiki/topics/{topic}.md#Overview
- Связанная работа → wiki/papers/*.md#Related + wiki/concepts/*.md#Comparison
- Метод → wiki/methods/{method}.md (## Mechanism + ## Procedure) + wiki/concepts/{concept}.md (## Definition + ## Intuition)
- Эксперименты → wiki/experiments/*.md#Results + wiki/experiments/*.md#Analysis
- Заключение → wiki/ideas/*.md#Lessons_learned + wiki/concepts/*.md#Open_problems + wiki/topics/*.md#Open_problems + wiki/graph/open_questions.md

**3b. Написание LaTeX**

Следуя `shared-references/academic-writing.md`:
- Пишите в соответствии с планом абзацев для этого раздела
- Вставляйте цитаты `\cite{key}` (ключи сопоставлены из плана цитат)
- Вставляйте ссылки `\ref{fig:name}` / `\ref{tab:name}` на фигуры/таблицы
- Используйте символы, определённые в `math_commands.tex`
- Начинайте каждый абзац с предложения-тезиса
- Раздел Experiments: структура "сначала идея" ("Наша гипотеза — X. Для проверки мы...")

**3c. Удаление AI-маркеров**

Примените удаление AI-маркеров к каждому написанному разделу (согласно academic-writing.md):
1. Сканируйте и заменяйте словарь с AI-маркерами (delve, leverage, utilize, comprehensive...)
2. Удаляйте избыточную осторожность
3. Варьируйте начала предложений (избегайте последовательных идентичных структур)
4. Удаляйте предложения-заполнители (предложения, не добавляющие информации)
5. Обеспечивайте преобладание действительного залога
6. Проверяйте согласованность обозначений

**3d. Опциональная проверка Review LLM (--review)**

Если `--review` включён, для каждого раздела:

```
mcp__llm-review__chat:
  system: "Вы — старший ML-исследователь, проверяющий один раздел черновика статьи.
           Фокус: ясность, логическая последовательность, соответствие идеям/экспериментам, согласованность обозначений.
           Укажите на оставшиеся языковые паттерны, характерные для AI.
           Предложите конкретные переписывания для неясных мест."
  message: |
    ## Раздел: {название раздела}
    {содержимое LaTeX}

    ## Идеи, которые этот раздел должен поддерживать
    {идеи из списка идей плана}

    ## Проверьте этот раздел на:
    1. Явно ли он поддерживает целевые идеи?
    2. Ясен ли и точен ли текст?
    3. Остались ли языковые паттерны, характерные для AI?
    4. Согласованы ли обозначения с другими разделами?
    5. Нет ли пропущенного содержимого, которого рецензенты ожидают?
```

Отредактируйте раздел по обратной связи Review LLM (врезки; не переписывайте весь раздел).

### Шаг 4: Построение библиографии

Следуя `shared-references/citation-verification.md`:

1. Соберите все цитаты `\cite{key}`, использованные в разделах
2. Для каждой цитаты получите BibTeX из плана цитат PAPER_PLAN:
   - Верифицированные: запишите напрямую в `references.bib`
   - [UNCONFIRMED]: запишите в конец `references.bib` с комментарием `% [UNCONFIRMED]`
3. Исключите неиспользуемые записи (не используйте `\nocite{*}`)
4. Проверьте корректность формата BibTeX (каждая запись имеет title, author, year)
5. Выведите статистику библиографии:
   ```
   references.bib: {N} записей, {M} верифицировано, {K} [UNCONFIRMED]
   ```

### Шаг 5: Полная проверка статьи

После завершения всех разделов:

```
mcp__llm-review__chat:
  system: "Вы — старший ML-исследователь, выполняющий финальную проверку полного черновика статьи.
           Фокус: согласованность между разделами, нить идея-эксперимент (подтверждают ли эксперименты центральные идеи?),
           последовательность повествования, согласованность обозначений между разделами, ссылки на фигуры/таблицы.
           Это НЕ проверка построчно — фокус на структурных и аргументационных проблемах."
  message: |
    ## Полный черновик статьи
    {конкатенация LaTeX всех разделов}

    ## Карта доказательств
    {из PAPER_PLAN}

    ## Фокус проверки
    1. Рассказывает ли статья связную историю от Введения до Заключения?
    2. Все ли идеи из плана адекватно поддержаны в тексте?
    3. Есть ли несогласованность обозначений между разделами?
    4. Все ли фигуры/таблицы ссылаются и обсуждаются?
    5. Есть ли избыточность между разделами?
    6. Общая готовность к подаче (1-10)?
```

Внесите финальные корректировки по обратной связи Review LLM.

### Шаг 6: Финализация вывода

1. Убедитесь, что все файлы записаны в директорию `paper/`
2. Проверьте базовую целостность:
   - все файлы, на которые ссылаются `\input{sections/X}`, существуют
   - все файлы, на которые ссылаются `\includegraphics{figures/X}`, существуют
   - все ключи `\cite{key}` имеют соответствующую запись в references.bib
   - все `\ref{label}` имеют соответствующий `\label{label}`
3. Добавление в журнал:
   ```bash
   python3 tools/research_wiki.py log wiki/ \
     "paper-draft | написана статья для {venue} '{title}' | {N} разделов, {M} фигур, {K} цитат ({V} верифицировано)"
   ```
4. Вывод в терминал:
   ```markdown
   # Написание статьи завершено

   ## Файлы
   - paper/main.tex (мастер-файл)
   - paper/sections/ ({N} файлов разделов)
   - paper/figures/ ({M} файлов фигур)
   - paper/references.bib ({K} записей, {V_count} [UNCONFIRMED])
   - paper/math_commands.tex

   ## Статус
   - Разделы написаны: {список}
   - Удаление AI-маркеров: применено
   - Проверка Review LLM: {да/нет, если да: общий балл}
   - Цитаты [UNCONFIRMED]: {количество} (разрешите до /paper-compile)

   ## Следующие шаги
   - Запустите `/paper-compile paper/` для компиляции и проверки
   - Разрешите цитаты [UNCONFIRMED] вручную
   - Запустите `/refine paper/main.tex --focus writing` для дальнейшей шлифовки
   ```

## Ограничения

- **Каждый раздел черпает из wiki**: не генерируйте содержимое из ничего; каждое техническое утверждение должно восходить к wiki-странице
- **BibTeX следует citation-verification.md**: извлекайте из DBLP/CrossRef/S2; не генерируйте из памяти LLM
- **Удаление AI-маркеров обязательно**: каждый раздел должен пройти этап шлифовки после написания; нельзя пропускать
- **Фигуры следуют academic-writing.md**: безопасные для дальтоников, размер шрифта >= 8pt, предпочтительно векторный формат
- **Анонимная подача**: не записывайте имена авторов, учреждения или благодарности (согласно требованиям анонимности площадки)
- **\nocite{*} запрещён**: цитируйте только фактически используемые записи
- **Согласованность обозначений**: все разделы используют единые символы из math_commands.tex
- **Резервное копирование существующего paper/ перед перезаписью**: не перезаписывайте напрямую; сначала сделайте резервную копию
- **Преобразование Wikilink → \cite**: ссылки `[[slug]]` в PAPER_PLAN преобразуются в `\cite{key}` в LaTeX
- **Таблицы используют booktabs**: без вертикальных линий или полной сетки

## Обработка ошибок

- **PAPER_PLAN не найден**: ошибка; предложите сначала запустить /paper-plan
- **Формат PAPER_PLAN неполный**: перечислите отсутствующие разделы; предложите повторно запустить /paper-plan
- **Wiki-страница не найдена** (идея/эксперимент/метод/статья, указанная в плане, не существует): предупредите и пропустите эту ссылку; аннотируйте как отсутствующую
- **Генерация фигуры не удалась** (ошибка matplotlib): выведите заполнитель `% TODO: generate figure {name}`; продолжите с другими разделами
- **Все извлечения BibTeX не удались**: используйте заполнители [UNCONFIRMED]; сообщите количество, требующее ручной обработки, в терминале
- **Review LLM недоступен** (режим --review): пропустите проверку разделов и перекрёстную проверку; аннотируйте "не проверено"
- **Шаблон площадки не найден**: используйте универсальный класс article; укажите в main.tex
- **Раздел слишком длин** (превышает бюджет страниц плана): предупредите; предложите перенести в приложение или сжать
